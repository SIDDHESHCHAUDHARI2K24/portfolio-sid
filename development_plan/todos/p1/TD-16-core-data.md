# TD-16: Core Data Foundations — Base/Mixins, Audience, TopicTag, Publishable, Registry + Migration

**Phase:** P1 · **Wave:** 5 · **Executor:** agent · **Effort:** L (2–3 days)
**Source:** development-plan-P1.md → P1.T1 (S1–S4)
**Depends on:** TD-07 · **Blocks:** TD-17, TD-18, TD-19

## Purpose
Everything in `core/` is imported by every feature slice; errors here are the
only ones that ripple across all of Phase 2. Establish the declarative base
and mixins, the audience enum, shared topic tags, the publishing mixin, and
the first real migration — once, so nine feature slices never reinvent them.

## Paths
- Create: `backend/app/core/models.py`, `backend/app/core/queries.py`, `backend/app/core/models_registry.py`
- Modify: `backend/alembic/env.py` (import registry), `docs/conventions.md`, new file under `backend/alembic/versions/`

## Steps
1. `models.py`: `Base(DeclarativeBase)`; `UUIDMixin` with `id: Mapped[UUID] = mapped_column(postgresql.UUID(as_uuid=True), primary_key=True, default=uuid4)` — never a string column (index efficiency, rejects malformed values); `TimestampMixin` with `created_at`/`updated_at` as `DateTime(timezone=True)`, UTC, `default=func.now()` and `onupdate=func.now()`; `SortableMixin` with integer `sort_order` (Books, Skills, Certifications will want it — retrofitting means nine migrations)
2. `Audience` as Python `enum.StrEnum`: `RECRUITERS`, `TECHIES`, `INVESTORS`, `FOUNDERS`, `PERSONAL`; persist via native Postgres enum `SAEnum(Audience, name="audience")`. `DEFAULT` is a separate Python-only sentinel for the uncategorised view — it must never be a database enum value
3. `TopicTag` model: `id`, `slug` (unique, lowercase, indexed), `label`, `description`. Association tables per content type (`timeline_topic_tags` now, `project_topic_tags` later) — never a polymorphic tag table (polymorphic loses FK integrity and queries poorly)
4. `PublishableMixin`: `status: Mapped[PublishStatus]` (`DRAFT`/`SCHEDULED`/`PUBLISHED`), `publish_at: Mapped[datetime | None]`, `published_at: Mapped[datetime | None]`; composite index on `(status, publish_at)`
5. `queries.py`: `public_filter(model)` returning `or_(model.status == PUBLISHED, and_(model.status == SCHEDULED, model.publish_at <= func.now()))` — the only sanctioned public read path; no endpoint reimplements it; admin queries bypass it explicitly
6. `models_registry.py` imports every feature `models` module; `alembic/env.py` imports the registry so `Base.metadata` is fully populated — a forgotten import produces a silently empty migration
7. `alembic revision --autogenerate` → first real migration (enum type, tags, association tables); hand-review before applying
8. `docs/conventions.md`: registry-import rule for new slices; `ALTER TYPE` caveat — adding a Postgres enum value is not autogenerated by Alembic and must be written by hand, or the migration appears to succeed and doesn't

## Tests
- Scratch model inheriting all mixins migrates cleanly; timestamps populate automatically
- `updated_at` changes on update; `created_at` does not
- `public_filter`: draft excluded; scheduled with past `publish_at` included; future excluded
- `TopicTag` unique slug enforcement; association table enforces referential integrity on delete
- Audience enum persists and round-trips

## Invariants
- `postgresql.UUID(as_uuid=True)` for all primary keys — no enumerable IDs, no string UUID columns
- All timestamps stored UTC
- `DEFAULT` audience never enters the database enum
- One association table per content type; never polymorphic tag joins
- `public_filter` is the only sanctioned public read path
- One migration per feature branch, generated against current `origin/main`, never hand-edited `down_revision`
